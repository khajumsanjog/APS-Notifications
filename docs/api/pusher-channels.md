# Pusher Channels & WebSocket Protocol Reference

APS is a fully compatible, drop-in replacement for Pusher Channels. It implements both the **Pusher v7 WebSocket Protocol** and the **Pusher REST Ingestion API**.

---

## 1. WebSocket Protocol Specification

Clients connect to the WebSocket gateway using the standard Pusher URL format:

```text
ws://<host>:<port>/app/<app_key>?protocol=7&client=js&version=8.4.0
wss://<host>:<port>/app/<app_key>?protocol=7&client=js&version=8.4.0
```

### Connection Handshake
Immediately upon connection establishment, APS sends a `pusher:connection_established` event containing a unique `socket_id` and the client ping activity timeout:

```json
{
  "event": "pusher:connection_established",
  "data": "{\"socket_id\":\"1002.4819284\",\"activity_timeout\":120}"
}
```

### Heartbeat (Ping / Pong)
To maintain connectivity across proxies and stateful firewalls, the server periodically sends ping requests or expects client pings:

```json
// Client -> Server (or Server -> Client)
{ "event": "pusher:ping", "data": {} }

// Response
{ "event": "pusher:pong", "data": {} }
```

## 2. Channel Subscriptions

### A. Public Channels
Public channels do not require authentication:

```json
// Client -> Server
{
  "event": "pusher:subscribe",
  "data": {
    "channel": "donations"
  }
}

// Server -> Client
{
  "event": "pusher_internal:subscription_succeeded",
  "channel": "donations"
}
```

### B. Private Channels (`private-*`)
Private channels require an HMAC-SHA256 signature generated by your application backend using your `app_secret`:

```json
// Client -> Server
{
  "event": "pusher:subscribe",
  "data": {
    "channel": "private-account-123",
    "auth": "aps_key_demo_12345:8b7a3...c91e"
  }
}
```

**Signature Calculation**:
```text
string_to_sign = socket_id + ":" + channel_name
auth_signature = HMAC_SHA256(string_to_sign, app_secret)
auth = app_key + ":" + auth_signature
```

### C. Presence Channels (`presence-*`)
Presence channels track online members and register custom user data:

```json
// Client -> Server
{
  "event": "pusher:subscribe",
  "data": {
    "channel": "presence-chat-room",
    "auth": "aps_key_demo_12345:e4d1...2b8c",
    "channel_data": "{\"user_id\":\"usr_42\",\"user_info\":{\"name\":\"Sita Sharma\"}}"
  }
}

// Server -> Client (initial member list)
{
  "event": "pusher_internal:subscription_succeeded",
  "channel": "presence-chat-room",
  "data": "{\"presence\":{\"count\":1,\"ids\":[\"usr_42\"],\"hash\":{\"usr_42\":{\"name\":\"Sita Sharma\"}}}}"
}

// Broadcast to other channel members when a user joins
{
  "event": "pusher:member_added",
  "channel": "presence-chat-room",
  "data": "{\"user_id\":\"usr_99\",\"user_info\":{\"name\":\"Bikash\"}}"
}

// Broadcast to other channel members when a user disconnects
{
  "event": "pusher:member_removed",
  "channel": "presence-chat-room",
  "data": "{\"user_id\":\"usr_99\"}"
}
```

### D. Client Events (`client-*`)
Clients subscribed to private or presence channels can trigger events directly to peers:

```json
// Client -> Server
{
  "event": "client-typing-indicator",
  "channel": "private-chat-100",
  "data": { "typing": true }
}
```
*Note: Client events are immediately dispatched to all other peers subscribed to that channel (excluding the sender `socket_id`).*

## 3. Server REST Ingestion API

Base URL: `http://localhost:8080` (or `https://aps.khajumsanjog.com`)

### Authentication
Server requests support standard **Pusher HMAC-SHA256 query signatures** or **Bearer tokens**:

```http
POST /apps/100001/events?auth_key=KEY&auth_timestamp=1788972000&auth_version=1.0&body_md5=HASH&auth_signature=SIG
```
Or via HTTP Header:
```http
Authorization: Bearer <jwt_or_api_key>
```

---

### `POST /apps/{app_id}/events`
Publish an event to one or more channels.

#### Request Body
```json
{
  "name": "donation_received",
  "channels": ["donations", "donations-live"],
  "data": {
    "donor": "Ram Sharma",
    "amount_npr": 5000
  },
  "socket_id": "1002.4819284",
  "info": "user_count"
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `name` | `string` | Event name (required) |
| `channels` | `string[]` | Array of channel names to broadcast to (required) |
| `data` | `object` or `string` | Payload (serialized as JSON) (required) |
| `socket_id` | `string` | Exclude this socket ID from receiving the broadcast (optional) |
| `info` | `string` | Comma-separated list of attributes (e.g. `user_count`) (optional) |

#### Response (`200 OK`)
```json
{}
```

---

### `POST /apps/{app_id}/batch_events`
Publish up to 10 events across different channels in a single atomic request.

#### Request Body
```json
{
  "batch": [
    {
      "channel": "orders",
      "name": "order_created",
      "data": { "order_id": "ord_101" }
    },
    {
      "channel": "inventory",
      "name": "stock_reduced",
      "data": { "sku": "SKU-99", "quantity": 1 }
    }
  ]
}
```

#### Response (`200 OK`)
```json
{}
```

---

### `GET /apps/{app_id}/channels`
List currently occupied channels in the application cluster.

#### Query Parameters
- `filter_by_prefix` (`string`, optional): Filter channels by prefix (e.g. `presence-`)
- `info` (`string`, optional): Request extra attributes (e.g. `user_count`)

#### Response (`200 OK`)
```json
{
  "channels": {
    "donations": {},
    "presence-room-1": {
      "user_count": 3
    }
  }
}
```

---

### `GET /apps/{app_id}/channels/{channel_name}`
Get details for a single channel.

#### Response (`200 OK`)
```json
{
  "occupied": true,
  "user_count": 5
}
```

---

### `GET /apps/{app_id}/channels/{channel_name}/users`
List user IDs currently in a presence channel.

#### Response (`200 OK`)
```json
{
  "users": [
    { "id": "usr_1001" },
    { "id": "usr_1002" }
  ]
}
```

---

### `POST /apps/{app_id}/channels/{channel_name}/terminate_connections`
Forcibly terminates all active client WebSocket connections on a specific channel.

#### Response (`200 OK`)
```json
{
  "status": "terminated"
}
```

## 4. APS Advanced Real-Time Extensions

### `GET /apps/{app_id}/channels/{channel_name}/history`
APS supports message replay so late-joining clients can recover recent channel history.

#### Query Parameters
- `limit` (`int`, optional, default `50`, max `100`): Number of messages to retrieve.

#### Response (`200 OK`)
```json
{
  "channel": "my-channel",
  "messages": [
    {
      "id": 1,
      "app_id": "100001",
      "channel_name": "my-channel",
      "event_name": "chat_message",
      "payload": "{\"text\":\"Hello World\"}",
      "socket_id": "1002.4819284",
      "created_at": "2026-09-09T22:30:00Z"
    }
  ]
}
```

---

### `POST /apps/{app_id}/broadcast`
Unified Real-Time WebSocket & Push Notification Broadcast. In a single call, APS sends a WebSocket event to live clients and dispatches a push notification via APS Beams to offline devices.

#### Request Body
```json
{
  "channel": "announcements",
  "event": "new_alert",
  "payload": {
    "title": "Severe Weather Warning",
    "severity": "high"
  },
  "push_notification": {
    "title": "Severe Weather Warning",
    "body": "Stay indoors. Severe weather warning issued.",
    "interest": "announcements"
  }
}
```

#### Response (`200 OK`)
```json
{
  "status": "broadcasted",
  "channel": "announcements",
  "push_publish_id": "pub_f8a9e21d"
}
```
